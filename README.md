Docker is a platform for developers and sysadmins to build, share, and run applications in containers, packaging code and dependencies together for consistent deployment across environments.

**Areas:** Cloud · Containers · Developer Tools · DevOps · Infrastructure · Microservices · Docker

## Docker on APIs.io

Everything profiled for Docker is published on APIs.io rather than in this repository. Start at the provider page — **[apis.io/providers/docker/](https://apis.io/providers/docker/)** — or go straight to one of the APIs or properties below.

### APIs (15)

- [Docker Config API](https://apis.io/apis/docker/docker-config-api/) — Configs are application configurations that can be used by services. Swarm mode must be enabled for these endpoints to work.
- [Docker Container API](https://apis.io/apis/docker/docker-container-api/) — Create and manage containers.
- [Docker Distribution API](https://apis.io/apis/docker/docker-distribution-api/) — The Distribution API from Docker — 1 operation(s) for distribution.
- [Docker Exec API](https://apis.io/apis/docker/docker-exec-api/) — Run new commands inside running containers. Refer to the [command-line reference](https://docs.docker.com/engine/reference/commandline/exec/) for more…
- [Docker Image API](https://apis.io/apis/docker/docker-image-api/) — The Image API from Docker — 15 operation(s) for image.
- [Docker Network API](https://apis.io/apis/docker/docker-network-api/) — Networks are user-defined networks that containers can be attached to. See the [networking documentation](https://docs.docker.com/network/) for more…
- [Docker Node API](https://apis.io/apis/docker/docker-node-api/) — Nodes are instances of the Engine participating in a swarm. Swarm mode must be enabled for these endpoints to work.
- [Docker Plugin API](https://apis.io/apis/docker/docker-plugin-api/) — The Plugin API from Docker — 11 operation(s) for plugin.
- [Docker Secret API](https://apis.io/apis/docker/docker-secret-api/) — Secrets are sensitive data that can be used by services. Swarm mode must be enabled for these endpoints to work.
- [Docker Service API](https://apis.io/apis/docker/docker-service-api/) — Services are the definitions of tasks to run on a swarm. Swarm mode must be enabled for these endpoints to work.
- [Docker Session API](https://apis.io/apis/docker/docker-session-api/) — The Session API from Docker — 1 operation(s) for session.
- [Docker Swarm API](https://apis.io/apis/docker/docker-swarm-api/) — Engines can be clustered together in a swarm. Refer to the [swarm mode documentation](https://docs.docker.com/engine/swarm/) for more information.
- [Docker System API](https://apis.io/apis/docker/docker-system-api/) — The System API from Docker — 6 operation(s) for system.
- [Docker Task API](https://apis.io/apis/docker/docker-task-api/) — A task is a container running on a swarm. It is the atomic scheduling unit of swarm. Swarm mode must be enabled for these endpoints to work.
- [Docker Volume API](https://apis.io/apis/docker/docker-volume-api/) — Create and manage persistent storage that can be attached to containers.

## How this profile is made

API Evangelist profiles a company's public API surface the way a developer would find it: the website, developer portal and documentation, the specifications it publishes, its public repositories, and its pricing, status and changelog pages. From that it derives the properties above — contracts split per API, workflows, schemas, collections, governance rules, plans and rate limits — and scores them against the published [Kin Score rubric](https://github.com/api-evangelist/kin-score).

The artifacts are published on [APIs.io](https://apis.io), not in this repository. This repository is the public record for Docker: the place to say something is wrong, missing or out of date, and to ask for a re-score or a removal.
